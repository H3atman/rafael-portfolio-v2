## Architecture

This is a Vite 8 portfolio site using React Router v7 in framework mode with React 19, TypeScript, and Tailwind CSS 4.

The site is fully prerendered: `react-router.config.ts` enumerates every route (`/`, `/projects`, and one per published project) and `npm run build` writes static HTML for each. There is no request-time rendering and no filesystem access at runtime.

### Content System

Projects are MDX files in `content/projects/` with YAML frontmatter:
```yaml
---
title: "Project Name"
description: "Brief description"
date: "2025-12-15"
tags: ["Tag1", "Tag2"]
thumbnail: "/projects/image.jpg"
---
```

**Drafts live in `content/drafts/`, not behind a `hidden:` flag.** Only `content/projects/`
is globbed, so a draft's prose is never compiled into the client bundle. A `hidden: true`
flag would still ship the full text to the browser — it would only hide the link — so
`lib/content.ts` throws at build time if it finds one in `content/projects/`. To unpublish a
project, `git mv` it to `content/drafts/`.

Content is indexed at **build time**. `lib/content.ts` uses `import.meta.glob` over
`content/projects/*.mdx`; each file is compiled by `@mdx-js/rollup` into a component plus a
`frontmatter` export. Nothing reads the filesystem at runtime.

Data functions in `lib/content.ts`:
- `getAllProjects()` - Returns all projects sorted by date (newest first)
- `getProjectBySlug(slug)` - Returns single project; `content` is a React component, not a string. Returns null for unknown slugs.
- `getRecentProjects(count)` - Returns latest N projects

`readingTime` is injected into each file's frontmatter by `plugins/remark-reading-time.ts`
during the MDX transform. Do not try to read MDX source via a `?raw` glob — the MDX plugin
intercepts it and you get a component instead of a string.

### Routing

Routes are declared in `app/routes.ts` and live in `app/routes/`. `app/root.tsx` is the HTML
shell (former `app/layout.tsx`). Per-route `<head>` output comes from each route's `meta()`
export, built through the `buildMeta()` helper in `lib/meta.ts`, which reproduces the old
Next.js `"%s | Rafael Portfolio"` title template, canonical, OpenGraph and Twitter tags.

### Component Architecture

All components render on both server and client. There are no `"use client"` directives —
they are a Next.js concept and were removed in the migration.

### Shadcn/UI Configuration

Configured in `components.json`:
- Style: `radix-lyra`
- Icon library: `hugeicons` (@hugeicons/react)
- Path aliases: `@/components`, `@/lib`, `@/components/ui`

Components use Class Variance Authority (CVA) for variants.

### Theming

- Dark/light mode via `next-themes` with ThemeProvider in `app/root.tsx` (the package name says "next" but it is framework-agnostic)
- CSS variables defined in `app/globals.css` using OKLCH color format
- Light mode: `:root` selector, Dark mode: `.dark` selector

### Configuration

Environment variables (`.env.local`). The `NEXT_PUBLIC_` prefix is retained deliberately —
production already has these names set — via `envPrefix` in `vite.config.ts`. Read them with
`import.meta.env`, not `process.env`:
- `NEXT_PUBLIC_BOOKING_URL` - Cal.com booking link
- `NEXT_PUBLIC_SITE_URL` - Production domain (defaults to rvcodes.com)
- `NEXT_PUBLIC_POSTHOG_KEY` / `NEXT_PUBLIC_POSTHOG_HOST` - PostHog analytics

Centralized config in `lib/config.ts` and SEO metadata in `lib/seo-config.ts`.

### SEO

- Per-route metadata via `meta()` exports + `lib/meta.ts`
- JSON-LD structured data (Website, Person, Article schemas)
- `sitemap.xml` and `robots.txt` are generated by `scripts/generate-seo-files.mjs`, run
  automatically via the `postbuild` script. They are NOT routes.
- The `/project` -> `/projects` permanent redirect exists twice on purpose: as a route
  (`app/routes/project-redirect.ts`) for the Node server, and in `vercel.json` for static hosting.
